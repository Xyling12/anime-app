# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выпускаются только для последней версии AniPulse.
Актуальная версия указана в [CHANGELOG.md](CHANGELOG.md).

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Воспользуйтесь одним из способов:

- [GitHub Security Advisory](https://github.com/Xyling12/anime-app/security/advisories/new) — предпочтительно;
- форма обратной связи на [anipulsetv.ru](https://anipulsetv.ru).

Пожалуйста, приложите:

- описание уязвимости и её потенциальное влияние;
- шаги воспроизведения или proof-of-concept;
- затронутый компонент (`app/`, `web/app/`, `server/`) и версию.

Мы отвечаем в течение 72 часов и держим вас в курсе до выпуска исправления.
Просьба не раскрывать детали публично, пока патч не выпущен.

## Что уже сделано

### Android-клиент

- Настройки и токен авторизации — в `EncryptedSharedPreferences`: значения шифруются
  AES-256-GCM ключом из Android Keystore, который не покидает аппаратное хранилище.
- Локальная база (прогресс просмотра, списки, избранное) шифруется SQLCipher.
  Пароль базы — 256 бит из `SecureRandom`, лежит в том же хранилище под ключом Keystore.
- Резервное копирование в облако и перенос данных на новое устройство запрещены
  (`allowBackup=false` + `data-extraction-rules` со всеми исключёнными доменами).
- Только системные корневые сертификаты (`network_security_config`): подставной CA,
  установленный на устройство, не даёт прочитать трафик приложения.
- Открытый HTTP невозможен (`usesCleartextTraffic=false`).
- Проверка подписи APK на старте (`AppIntegrity`): перепакованная сборка не запускается
  и не планирует фоновых задач.
- Release обфусцирован R8, отладочные логи вырезаются из сборки.
- Разрешений всего два: `INTERNET` и `POST_NOTIFICATIONS`.

### Сервер
- Пароли хранятся как scrypt-хеши с солью, сессионные токены подписаны HMAC-SHA256.
- API-шлюз слушает только loopback и запускается в systemd-песочнице;
  внешний доступ — только через Caddy с HSTS и ограничивающими заголовками.
- Rate limiting на аутентификацию, профиль и проксирование; ограничение размера
  входящих и upstream-ответов.
- Секреты не хранятся в репозитории; pre-commit hook (`.githooks/pre-commit`)
  и CI-workflow [`security.yml`](.github/workflows/security.yml) проверяют это на каждом коммите.
