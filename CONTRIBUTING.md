# Как участвовать в разработке

Спасибо за интерес к AniPulse. Ниже — минимум, который нужно знать.

## Перед началом

- Обсудите крупные изменения в issue, прежде чем писать код.
- Уязвимости — не в issue, а по процедуре из [SECURITY.md](SECURITY.md).

## Окружение

Требования и команды сборки — в [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

## Ветки и коммиты

- Ветки: `feat/<кратко>`, `fix/<кратко>`, `docs/<кратко>`, `ops/<кратко>`.
- Коммиты в стиле Conventional Commits, тело — на русском:

  ```
  fix(player): не сбрасывать таймкод при смене озвучки
  ```

## Перед пул-реквестом

```bash
./gradlew test lint      # Android
node --test "server/tests/*.test.js"   # шлюз
cd web/app && pnpm lint && pnpm build   # веб
```

Включите pre-commit hook, который проверяет коммиты на секреты:

```bash
git config core.hooksPath .githooks
```

## Защита данных

В приложении есть механизмы защиты, которые снаружи выглядят как лишний код и
легко теряются при рефакторинге: шифрование токена и локальной базы, проверка
подписи APK, ограничение доверенных сертификатов. Список с указанием, что именно
сломается при удалении каждого, — в [CLAUDE.md](CLAUDE.md); модель угроз и
границы защиты — в [docs/ANDROID_SECURITY.md](docs/ANDROID_SECURITY.md).

Трогать их можно только осознанно и с обоснованием в описании пул-реквеста.

## Чего не делать

- Не коммитить `keystore.properties`, `gradle.properties`, `.env`, ключи и токены.
- Не добавлять IP-адреса, домены и пароли боевой инфраструктуры в код и документацию —
  используйте переменные окружения и плейсхолдеры.
- Не добавлять зависимости без необходимости: у сервера жёсткий лимит памяти.
