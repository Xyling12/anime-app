# Архитектура AniPulse

## Общая схема

```
┌──────────────┐      ┌──────────────┐
│  Android     │      │   Веб-клиент │
│  app/        │      │   web/app/   │
└──────┬───────┘      └───────┬──────┘
       │                      │
       └──────────┬───────────┘
                  │  HTTPS
        ┌─────────▼──────────┐
        │  Caddy (80/443)    │  TLS, HSTS, защитные заголовки
        └─────────┬──────────┘
                  │  127.0.0.1
        ┌─────────▼──────────┐
        │  API-шлюз          │  server/gateway.js
        │  Node.js + SQLite  │  аккаунты, соц. функции, прокси, кеш
        └─────────┬──────────┘
                  │
   ┌──────────────┼───────────────┬───────────────┐
   ▼              ▼               ▼               ▼
Shikimori     видео-              AniSkip      AniList /
(каталог)     источники        (тайминги)      Jikan (постеры)
```

Клиенты никогда не ходят во внешние API напрямую: всё проксируется шлюзом.
Это решает три задачи — доступность источников из сетей российских
провайдеров, единый кеш (постеры и метаданные) и сокрытие серверных
токенов от клиента.

## Android-приложение (`app/`)

Kotlin + Jetpack Compose, single-activity, MVVM.

| Слой | Где | Что делает |
|---|---|---|
| UI | `ui/` | Compose-экраны и `ViewModel` на каждый раздел: каталог, тайтл, плеер, библиотека, расписание, профиль |
| Данные | `data/` | Retrofit-клиенты (`Api`, `GatewayApi`), репозитории, `SettingsStore` на `EncryptedSharedPreferences` |
| Локальная БД | `data/db/` | Room: прогресс серий, избранное, скрытые из «Продолжить» |
| Видео | `data/video/` | Интерфейс `VideoSource` и его реализации; `PlaybackSession` для плеера |
| Загрузки | `data/download/` | Скачивание серий и офлайн-воспроизведение |
| DI | `di/` | Hilt-модули сети и базы данных |
| Фон | `notify/` | WorkManager: уведомления о новых сериях |
| Виджет | `widget/` | «Продолжить просмотр» на рабочем столе |

Плеер построен на Media3 ExoPlayer: один плеер на все источники, HLS,
выбор качества, жесты, PiP, автопропуск опенинга и эндинга по данным AniSkip
с эвристическим запасным вариантом.

Минимальная версия — Android 8.0 (API 26), целевая — API 35.

## API-шлюз (`server/`)

Node.js без внешних зависимостей — только стандартная библиотека. Слушает
loopback, наружу выставляется только через Caddy. Данные — в SQLite и JSON-файлах
с правами `0600` в каталоге с правами `0700`.

Основные группы эндпоинтов (`/alapi/…`):

| Группа | Назначение |
|---|---|
| `shikimori/*`, `anilibria/*`, `anilistcdn/*`, `malcdn/*` | прозрачное проксирование с кешем |
| `poster/{id}` | подбор обложки: AniList → Jikan/MAL, если её нет у Shikimori |
| `anilibria-updates` | лента свежих серий |
| `auth/*`, `profile`, `user`, `stats/me` | регистрация, вход, OAuth VK ID и Яндекс ID, профиль |
| `sync`, `ratings`, `rating` | синхронизация прогресса и списков, оценки |
| `comments`, `chat`, `dm/*`, `friends/*`, `notifications/*` | социальные функции |
| `reports`, `blocks`, `admin/*` | модерация: жалобы, блокировки, баны |
| `app-version`, `apk` | OTA-манифест и раздача сборки |

`proxy-security.js` задаёт белый список апстримов и правила проксирования;
`analytics-store.js` — агрегированная статистика; `backup.js` — резервные копии.

## Веб-клиент (`web/app/`)

Next.js 16 (App Router), React 19, TypeScript, Tailwind. Воспроизведение — `hls.js`,
серверное состояние — TanStack Query. Разделы повторяют мобильные: каталог,
страница тайтла, просмотр, расписание, профиль, чат, ЛС, друзья, а также
правовые страницы (пользовательское соглашение, политика конфиденциальности,
правила сообщества, страница для правообладателей).

> **Важно:** каталог `web/app` — не тот код, который работает на боевом сайте.
> Подробности и текущий статус расхождения — в [`web/app/README.md`](../web/app/README.md).

## Развёртывание (`server/deploy/`)

Эталонные конфигурации продакшена: `Caddyfile`, systemd-override с песочницей
для шлюза, правила fail2ban для SSH, скрипт проверки расхождения между
репозиторием и сервером (`check-deploy-drift.sh`). Пошаговый процесс выкладки —
в [`server/deploy/DEPLOY.md`](../server/deploy/DEPLOY.md).

Ни один файл в репозитории не содержит адресов, паролей и токенов боевой
инфраструктуры: они задаются переменными окружения или лежат на сервере вне git.
